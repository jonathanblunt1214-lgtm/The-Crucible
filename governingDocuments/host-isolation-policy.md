# Host isolation policy

The operator's machine and every GitHub server or hosted runner are execution environments. Neither is a Crucible component, knowledge source, managed project, authority, or resource to assimilate. A provider's ability to execute a job grants no authority beyond the owner's exact repository and workflow instruction.

The boundary is a selectively permeable cell membrane, not a prohibition on interaction. Authenticated, typed, project-bound, size-bounded, purpose-bound, and audited signals may cross only through explicit receptors such as repository gates, encrypted learning custody, signed oversight control, or owner-permitted external-AI/GPU gates. Unknown, secret-bearing, executable, oversized, unauthenticated, cross-project, or out-of-scope traffic is rejected or quarantined. Crossing the membrane grants neither assimilation nor proof authority.

Crucible may access only the explicitly opened or named project repository, explicitly configured project-scoped learning custody, and a disposable per-run temporary root. A repository listed in Crucible's governed repository manifest is opted in; a repository with a verified active Crucible injection record is also opted in for that injection's exact lifetime and scope. Cross-repository coordination is limited to allow-listed analysis, issue reporting, governed injection, or project-bound learning transport. Opt-in never permits assimilation or arbitrary writes. Crucible must not inventory unrelated files, applications, processes, accounts, devices, repositories, organizations, credentials or secrets, browser state, network shares, user-profile content, runner images, or host capabilities. It must not install startup entries, scheduled tasks, services, host tools, background agents, runner persistence, or profile state.

Native compiler analysis defaults to ephemeral GitHub-hosted runners. A local native operation is allowed only when it is essential to the interactive coding workflow, explicitly bounded to the opened project, produces no hidden persistence, and is controlled by the appropriate owner boundary. GPU execution is off by default and requires a short-lived, project- and workload-hash-bound permit signed by the owner's offline private key. The hard-stop file overrides every permit. Crucible stores only the public verification key and has no operation that creates, removes, or bypasses the owner's permit or hard stop.

Telemetry, tool availability, profile contents, runner images, GitHub metadata outside the exact job/repository boundary, host configuration, and incidental files are never candidate learning evidence. No local or GitHub host observation can satisfy a scientific proof stage, expand research scope, or grant authority.

ChatGPT and every other external AI provider are also outside Crucible. No payload may leave Crucible for an external AI unless the owner supplies a short-lived signed permit bound to the exact project, provider, payload hash, purpose, and allow-listed fields. Missing, expired, altered, or over-broad permits fail closed, and an owner-controlled offline hard stop overrides every permit. Crucible never sends credentials, secrets, private repository context outside the permitted fields, or learning-custody contents by implication.
